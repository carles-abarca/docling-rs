# docling-rs 1.0.5

This release fixes the crashes, silent content loss, ordering errors and chunk
budget overflow found by expanded attachment validation of v1.0.4.

## Corrections

- **DOCX robustness:** replace the docx-rs parsing path with bounded Office XML
  extraction. Corrupt ZIP/deflate/checksum/XML inputs return conversion errors
  instead of panicking. Reject excessive input size, expansion, entries or depth.
- **DOCX fidelity:** retain header/footer parts, hyperlink text, line breaks/tabs
  and nested table text. Deleted revision text is excluded.
- **PPTX:** follow presentation relationship order, including manually reordered
  slides, instead of lexical filenames. Preserve tables as structured table nodes
  so they survive chunking. Extract speaker notes. Read bytes directly without
  leaving temporary presentation files on parse errors.
- **HTML:** retain text in containers, preserve inline word/space boundaries,
  maintain block order and exclude scripts/styles/templates. Reject excessive depth.
- **Chunking:** split over-budget text without whitespace on UTF-8 boundaries.
  Add `HybridChunker::try_chunk` to return an error for budgets too small for a
  Unicode scalar or contextual metadata. The CLI now uses this strict API.
- **PDF:** infer reading order for clear two-column layouts and disclose the
  heuristic through PartialSuccess/metadata. General layout reconstruction and
  OCR are not implied. CLI partial-conversion warnings are visible on stderr.

## Distribution

- The macOS DMG now contains universal PDFium matching the universal executable.
- Default PDFium lookup checks the executable directory and app Frameworks before
  the legacy current-directory/system lookup. Explicit paths still never fallback.
- Linux bundles PDFium Chromium 7350, verified against the pinned SHA-256, with
  its license notices. Release gates exercise PDF regressions and packaged-CLI
  loading on each native platform runner.
- CI formatting/Clippy and workspace validation are aligned with current sources;
  manual releases use the requested tag and the matching checked-in release notes.

## Validation

- Ten targeted regressions pass locally, including native PDFium.
- **3,948 conversion attempts completed with controlled outcomes** across the
  extended matrix and follow-up soaks; no worker panics.
- **47/49 synthetic contracts pass**. The two remaining content expectations are
  TXT and scanned PDF OCR, which this release does not implement.
- **20/20 seeded corrupt inputs handled** (v1.0.4: 17/20).
- Two 1,000-cycle DOCX/PDF runs reach ~35 MiB RSS and plateau from about cycle 200.
  The 500-page workload peaks at ~60 MiB sampled RSS. These are observations, not
  memory limits, proof of no leaks, or a qualification of untrusted inputs.
- Real-corpus token coverage improves for PPTX; layout/semantic fidelity still
  requires separate validation. Performance remains dominated by chunking.

See [the validation report](https://github.com/carles-abarca/docling-rs/blob/v1.0.5/docs/validation-v1.0.5.md)
for methodology, measured timings and limitations.

## Integration notes

Chunk boundaries, slide order and extracted content can change; rebuild persisted
chunks when upgrading. Inspect partial-conversion warnings. Use `try_chunk` for
strict context admission: the older infallible iterator preserves content when an
impossibly small budget cannot fit it. No Python environment is required.

OCR, faithful complex PDF/table rendering, hard process memory ceilings and native
cancellation remain separate work. macOS packaging includes both architectures,
but the native runner test does not substitute for testing both Intel and ARM64.
