# docling-rs 1.0.4

This release fixes silent content loss in document extraction and RAG chunking,
corrects token counting, and improves PDF embedding support.

## Fixes and improvements

- **DOCX:** retain table contents, including text from nested tables, and preserve
  run line breaks and tabs.
- **HTML:** extract headings, paragraphs, lists and tables in document order;
  exclude script and style content from extracted blocks.
- **Excel:** retain worksheet names and formula text even when a workbook has no
  cached formula results. When present, cached values and formulas are both
  included. Worksheet errors now propagate instead of silently skipping a sheet.
- **Table chunking:** preserve header-only tables, single-column rows, rows with
  an empty first cell, unlabeled columns and extra cells in ragged rows.
  Markdown table export also escapes pipes and line breaks.
- **Token counting:** disable tokenizer padding and truncation consistently.
  Empty text and `hello` now count as 0 and 1 tokens, instead of 128 each with
  the embedded tokenizer.
- **PDFium:** pin `pdfium-render` to 0.8.37 with the API 7350 binding, tested
  against the repository's existing macOS ARM64 PDFium library. Add
  `DocumentConverter::with_pdfium_library(path)` and
  `PdfBackend::with_library_path(path)` for explicit dynamic-library selection.
  Invalid explicit paths fail without falling back to a different library.
- **PDF completeness:** textless pages now produce `PartialSuccess` with
  `textless_pages` and `conversion_warnings` document metadata.
- Correct README examples for the public Markdown/text export functions and add
  synthetic regression fixtures and evaluation documentation.

## Integration notes

Token counts and chunk boundaries change. Table chunk serialization now includes
its first row and labels subsequent values by column where possible. Rebuild
persisted document chunks if your application depends on the previous output.

Consumers should inspect conversion status and warnings. Textless pages can be
blank or scanned: this release **does not add OCR**. Plain TXT still has no
backend. Formula text is preserved, not evaluated. PDF extraction remains
text-based and does not reconstruct complex tables/layouts.

The explicit PDFium path should point to a trusted packaged library file.
Default converter lookup remains unchanged. PDFium runtime validation for this
change was performed on Apple Silicon; Intel macOS and Windows require further
runtime validation. Linux requires a separately available PDFium library when
one is not included in the distribution.

## Validation

- Workspace tests on macOS ARM64: **156 passed, 0 failed, 18 ignored**.
- Separate PDFium regression test: **passed** (normally ignored without a library).
- Clippy completed; one existing `manual_div_ceil` warning remains.
- LG synthetic evaluation: **15/17** original expectations met. The two remaining
  cases are unsupported TXT and a scanned PDF requiring OCR. All expected markers
  in supported text-extraction cases survive chunking.
- Peak RSS in this small-fixture evaluation: **28.5 MiB**. This is a measurement,
  not a memory limit or validation against large/hostile documents.

Local validation used Rust 1.98.1. The workspace's historical Rust 1.75 declaration
is not a verified minimum with current unlocked dependencies.

See [attachment fidelity report](https://github.com/carles-abarca/docling-rs/blob/v1.0.4/docs/attachment-fidelity.md)
for detailed behavior and limitations.
