Architecture Overview

docling-rs is built with a modular, workspace-based architecture that enables flexible deployment and easy extension.

Workspace Structure

docling-rs/
├── crates/
│   ├── docling-rs/              # Main facade library
│   ├── docling-rs-core/         # Core types and traits
│   ├── docling-rs-cli/          # Command-line interface
│   └── docling-rs-formats/      # Format backends
│       ├── markdown/
│       ├── html/
│       ├── csv/
│       ├── docx/
│       ├── xlsx/
│       ├── pptx/
│       └── pdf/
├── manual/                      # Documentation
├── pdfium/                      # PDFium library binaries
└── scripts/                     # Build and test scripts

Core Components

docling-rs (Facade)

The main crate that users import. Re-exports all public types and provides the DocumentConverter high-level API.

Key Responsibilities

  • Re-export public API from core and format crates
  • Provide DocumentConverter convenience wrapper
  • Configure feature flags for format backends

docling-rs-core

Foundation crate containing shared types, traits, and utilities:

  • Data Model - DoclingDocument, DocumentNode, NodeType
  • Traits - Backend, Pipeline
  • Chunking - HierarchicalChunker, HybridChunker
  • Errors - ConversionError, ChunkingError

docling-rs-cli

The command-line interface binary. Depends on the facade library and provides:

  • Argument parsing with clap
  • Batch processing
  • Progress reporting
  • Output formatting

Document Model

All documents are converted to a unified DoclingDocument model:

Structure
DoclingDocument
├── name: String
├── source: DocumentSource
└── nodes: Vec<DocumentNode>
    └── DocumentNode
        ├── item: NodeItem
        │   ├── node_type: NodeType
        │   ├── text_content: String
        │   └── position: Option<SourcePosition>
        └── metadata: Option<NodeMetadata>

Node Types

Structural

  • Heading
  • Paragraph
  • List / ListItem

Content

  • Text
  • Code
  • Quote

Tabular

  • Table
  • TableRow
  • TableCell

Media

  • Image
  • Link

Backend Trait

Format backends implement the Backend trait:

Rust
pub trait Backend: Send + Sync {
    /// Backend name for identification
    fn name(&self) -> &str;

    /// Formats this backend can handle
    fn supported_formats(&self) -> &[InputFormat];

    /// Convert an input document
    fn convert(
        &self,
        input: &InputDocument
    ) -> Result<ConversionResult, ConversionError>;
}

Pipeline Architecture

The SimplePipeline routes documents to appropriate backends:

Rust
// Pipeline selects backend based on input format
impl Pipeline for SimplePipeline {
    fn execute(
        &self,
        input: &InputDocument
    ) -> Result<ConversionResult, ConversionError> {
        // Find backend that supports this format
        for backend in &self.backends {
            if backend.supported_formats().contains(&input.format()) {
                return backend.convert(input);
            }
        }
        Err(ConversionError::NoBackendAvailable)
    }
}

Using Custom Pipeline

Rust
use docling_rs::{SimplePipeline, MarkdownBackend};

fn custom_pipeline() -> SimplePipeline {
    let mut pipeline = SimplePipeline::new();

    // Register only specific backends
    pipeline.register_backend(Box::new(MarkdownBackend::new()));
    pipeline.register_backend(Box::new(CustomBackend));

    pipeline
}

Build System

The workspace uses Cargo with feature flags for conditional compilation:

Terminal
# Build everything
cargo build --workspace

# Build CLI only
cargo build -p docling-rs-cli

# Build with specific features
cargo build -p docling-rs --features "markdown,html"

# Release build
cargo build --release -p docling-rs-cli
