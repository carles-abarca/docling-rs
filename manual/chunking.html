Chunking for RAG Applications

docling-rs provides intelligent chunking strategies designed specifically for Retrieval-Augmented Generation (RAG) applications. The chunking system splits documents into semantically meaningful pieces suitable for embedding and retrieval.

Why Chunk Documents?

Embedding models and LLM context windows have size limits. Chunking helps by:

  • ✓ Fitting context windows - Chunks match embedding model limits
  • ✓ Improving retrieval - Smaller, focused chunks retrieve better
  • ✓ Preserving meaning - Semantic boundaries keep context intact
  • ✓ Enabling metadata - Each chunk carries source information

Chunking Strategies

Hierarchical Chunker

The HierarchicalChunker respects document structure when splitting:

  • Splits at section boundaries (headings)
  • Preserves paragraph integrity when possible
  • Maintains parent-child relationships
  • Adds hierarchical context to chunks
Rust
use docling_rs::{DocumentConverter, HierarchicalChunker};

fn chunk_with_hierarchy() -> Result<(), Box<dyn std::error::Error>> {
    let converter = DocumentConverter::new();
    let result = converter.convert_file("document.pdf")?;
    let doc = result.document();

    // Create chunker with configuration
    let chunker = HierarchicalChunker::new()
        .with_max_chunk_size(512)     // Max characters per chunk
        .with_overlap(50);             // Overlap between chunks

    // Generate chunks
    let chunks = chunker.chunk(doc)?;

    for (i, chunk) in chunks.iter().enumerate() {
        println!("Chunk {}: {} chars", i + 1, chunk.text().len());
        println!("  Text: {}...", &chunk.text()[..50.min(chunk.text().len())]);
    }

    Ok(())
}

Hybrid Chunker

The HybridChunker combines hierarchical awareness with token-based sizing:

  • Uses tokenizer for accurate size estimation
  • Respects embedding model token limits
  • Balances structure preservation with size constraints
  • Ideal for production RAG systems
Rust
use docling_rs::{DocumentConverter, HybridChunkerBuilder};

fn chunk_with_tokens() -> Result<(), Box<dyn std::error::Error>> {
    let converter = DocumentConverter::new();
    let result = converter.convert_file("document.pdf")?;
    let doc = result.document();

    // Build hybrid chunker
    let chunker = HybridChunkerBuilder::new()
        .max_tokens(256)              // Token limit for embeddings
        .overlap_tokens(20)           // Token overlap
        .build()?;

    let chunks = chunker.chunk(doc)?;

    println!("Generated {} chunks", chunks.len());
    Ok(())
}

CLI Chunking

Enable chunking from the command line with the --chunk flag. Choose between hierarchical (structure-based) and hybrid (token-aware) strategies:

Terminal
# Hierarchical chunking (default) - preserves document structure
docling-rs document.pdf --chunk --to json

# Hybrid chunking - token-aware, ideal for embeddings
docling-rs document.pdf --chunk --chunk-strategy hybrid --to json

# Hybrid with custom token limit
docling-rs document.pdf --chunk --chunk-strategy hybrid --chunk-max-tokens 256 --to json

# Hybrid without merging small chunks
docling-rs document.pdf --chunk --chunk-strategy hybrid --chunk-merge-peers false --to json

# Batch chunking with hybrid strategy
docling-rs ./documents/ --chunk --chunk-strategy hybrid --chunk-max-tokens 512 --to json --output-dir ./chunks

Strategy Comparison

Feature Hierarchical Hybrid
Best for Preserving document structure Embedding models with token limits
Chunk sizing Based on document elements Based on token count
Large sections Kept as single chunk Automatically split
Small sections Kept separate Optionally merged

Chunk Metadata

Each chunk includes metadata for tracking and retrieval:

Field Description
chunk_index Zero-based index of the chunk
total_chunks Total number of chunks from this document
char_count Number of characters in the chunk
source_document Original document filename
headings Hierarchy of headings leading to this chunk

Best Practices

Choosing Chunk Size

Recommended Chunk Sizes
  • 256-512 tokens - Best for most embedding models
  • 1000+ chars - For longer context retrieval
  • Match your model - Check your embedding model's limits

Using Overlap

Overlap helps maintain context across chunk boundaries:

  • 10-20% overlap is typically effective
  • Higher overlap for documents with continuous narrative
  • Lower overlap for structured documents with clear sections

RAG Integration Example

Rust
use docling_rs::{DocumentConverter, HierarchicalChunker};

fn prepare_for_rag(path: &str) -> Result<Vec<(String, serde_json::Value)>, Box<dyn std::error::Error>> {
    // Convert document
    let converter = DocumentConverter::new();
    let result = converter.convert_file(path)?;
    let doc = result.document();

    // Chunk for embedding
    let chunker = HierarchicalChunker::new()
        .with_max_chunk_size(512)
        .with_overlap(50);

    let chunks = chunker.chunk(doc)?;

    // Prepare for vector store
    let documents: Vec<_> = chunks
        .iter()
        .map(|chunk| {
            let metadata = serde_json::json!({
                "source": path,
                "chunk_id": chunk.metadata().chunk_index(),
                "headings": chunk.metadata().headings(),
            });
            (chunk.text().to_string(), metadata)
        })
        .collect();

    Ok(documents)
}
